# 单文件 HTML 交互原型

## 目的

把 PRD 的**界面要素与流程**转换为可离线打开、可点击走通的 HTML 原型，用于评审与对齐，而不是静态截图。

## 何时使用

- PRD 完成后生成对应原型；
- 需要给业务方演示交互与状态时；
- 需要核验原型与 PRD 页面清单一致性时。

## 前置输入

1. 以 `prd/` 的页面/界面要素清单为**业务依据**，不得自行发明字段或状态。
2. 以 `<项目>/_meta/tech-stack.md`（0-1 由 `/ai-require-design` 阶段 0 落档；缺失则取 `.codebuddy/tech-stack.md` 系统默认）中的前端 UI 库为**视觉依据**，加载对应的 `references/visual-<ui-lib>.md` 视觉基线（默认 Element Plus → `visual-element-plus.md`）。
3. PRD §技术选型与 UI 约束节是 UI 库选择的**强制来源**，原型与本节逐字对齐。

## 工作流程

1. **提取页面清单**：从 PRD 汇总所有页面/区域，分配页面 ID（与功能 ID 对应）。
2. **套用骨架**：以 `assets/prototype-skeleton.html` 为单页基座，`assets/index-nav-skeleton.html` 为导航页基座。
3. **填充内容**：用真实感假数据渲染，覆盖关键取值形态；布局遵循 `references/page-layout-baseline.md`。
4. **实现交互**：页面内状态切换、校验反馈、弹窗、Toast、关键流程可点击走通。
5. **生成导航**：产出 `prototype/index.html`，按模块分组列出全部页面。
6. **一致性自检**：逐页对照 PRD 页面清单与字段/文案。

## 硬性要求

- **单文件自包含**：内联 CSS/JS，无 CDN、无外部字体/图片、无构建、无网络请求；双击可打开。
- **真实感假数据**：业务化命名，禁止 `test`/`aaa`/`示例1`；覆盖正常/边界/异常取值。
- **状态覆盖**：加载中 / 空数据 / 正常 / 错误 / 无权限（如适用），可界面切换。
- **交互反馈**：悬停/禁用态、表单校验提示、成功/失败提示、确认弹窗、重复提交防抖（二次确认弹窗按钮行为）。
- **文案逐字一致**：弹窗、Toast、空状态、报错文案**逐字取自 PRD 文案规范**（含标点），禁止改写或新造。
- **与 PRD 对齐**：页面清单、字段、状态、文案一一对应，不缺失、不越界；异常形态覆盖 PRD 异常六类（网络/空数据/报错/权限/重复操作/超限）中该页面适用的全部。

## 资源

- `assets/prototype-skeleton.html` — 单页原型骨架（内联样式 + 状态切换器 + 数据渲染占位）。
- `assets/index-nav-skeleton.html` — 原型导航页骨架。
- `references/page-layout-baseline.md` — 页面布局与样式基线（CSS 变量、通用组件样式）。

## 红线

- 禁止引入外部依赖或构建步骤；
- 禁止使用真实隐私/密钥/生产数据；
- 禁止发明 PRD 中不存在的字段或状态；
- 禁止改写或新造 PRD 之外的文案；
- 落盘前做敏感信息过滤。

## 输出校验（自检清单）

- [ ] 每个 HTML 均为单文件、离线可用；
- [ ] 状态可切换且覆盖齐全；
- [ ] 假数据真实感且覆盖边界；
- [ ] 页面与 PRD 清单一一对应；
- [ ] 全部文案与 PRD 文案规范逐字一致；
- [ ] 存在 `index.html` 导航页。
