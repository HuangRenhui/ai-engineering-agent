# 变更日志追踪

## 目的

持续沉淀项目的**变更（变更时间 + 变更明细）**，来源双通道：代码提交历史与需求拍板确认，合并为一份可追溯、追加式、不覆盖历史的变更日志。

## 何时使用

- 1+ 模式：从目标仓库 Git 历史挖掘变更；
- 任意模式：需求分析/评审过程中每次"拍板确认"当场记录变更；
- 需要合并两来源、生成/更新 `CHANGELOG.md` 时。

## 双来源

| 来源标识 | 采集时机 | 采集内容 |
|----------|----------|----------|
| `git-commit` | 进入 1+ 模式时 | 提交时间、提交说明、涉及文件/模块、short-sha |
| `decision` | 需求拍板确认**当下** | 变更内容（前→后）、影响范围、决策人、对话/文档证据 |

采集方法详见 `references/git-mining.md`。

## 统一字段（两来源归一化目标）

```yaml
- time:     "2026-09-14T10:30:00+08:00"   # 必填
  type:     decision                       # decision | git-commit
  summary:  "一句话变更点"                 # 必填
  detail:   "变更前 → 变更后"
  source:   "需求分析拍板 / git:<short-sha>"
  scope:    "F01 / 页面名 / 文件模块"
  decider:  "user / 角色名"                # decision 必填
  evidence: "对话轮次 / 文档锚点 / 提交链接"
```

## 工作流程

1. **采集**：产出原始素材 `changelog/_git-log.md`（Git 历史）与 `changelog/_decisions.md`（由需求侧 `<产出目录>/_meta/decisions.md` 归并而来，见 `requirement-analysis` 技能「工作流程 4」；模板见 `templates/`）。
2. **归一化**：把两条通道的素材映射为统一字段。
3. **合并**：按 `time` 倒序；以（`time` + `summary` + `source`）去重。
4. **落盘**：追加写入 `changelog/CHANGELOG.md`（模板见 `templates/CHANGELOG.md`），**永不去掉历史条目**。
5. **统计**：更新文件头部统计（条目总数、各来源数量、时间范围）。

## 追加式原则

- 只追加，不覆盖、不删除；
- 需修正历史错误时，**新增一条修正条目**说明更正内容与原因，原条目保留。

## Git 挖掘要点

- 按 `--scope` 过滤路径/模块，避免全量历史；
- **限量/分页**输出，避免超长日志；
- 仅使用只读命令（`git log` / `git show`）；
- 提交信息与差异中的敏感信息以占位符替代。

## 红线

- 禁止事后凭记忆补写 `decision` 条目；
- 禁止使用相对时间；
- 禁止覆盖既有变更记录；
- 落盘前做敏感信息过滤。

## 输出校验（自检清单）

- [ ] 两来源素材均已留存；
- [ ] 条目字段完整，`time`/`summary` 无缺失；
- [ ] 已按时间倒序并按规则去重；
- [ ] 历史条目未被覆盖或删除；
- [ ] 头部统计已更新。
