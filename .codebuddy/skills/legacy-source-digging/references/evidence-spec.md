# 证据与置信度标注规范

## 一、证据格式

统一格式：`<相对路径>:<行号>`，必要时附**最小充分片段**。

```
src/main/java/com/demo/order/OrderService.java:88
```

- 路径为**目标源码根目录的相对路径**，统一用 `/`。
- 行号指向**结论所依据的具体行**（方法签名、字段声明、注解、路由注册）。
- 范围证据可写成 `路径:起始行-结束行`。
- 多证据并列：`证据1；证据2`。

## 二、最小充分片段

只贴能支撑结论的最小片段，禁止整文件粘贴。

```java
// 证据：OrderService.java:88
@PostMapping("/orders")
public Result<OrderVO> create(@RequestBody OrderCreateDTO dto) { ... }
```

## 三、置信度三档

| 等级 | 标记 | 判定标准 | 是否可入正文 |
|------|------|----------|--------------|
| 确证 | `[确证]` | 有直接证据，逻辑可完整还原 | 可 |
| 推断 | `[推断]` | 证据不完整，依据命名/结构/调用链合理推导 | 可，但需保留标记 |
| 猜测 | `[猜测]` | 无直接证据，仅假设 | 否，仅入开放问题 |

## 四、常见结论类型的证据要求

| 结论类型 | 证据指向 |
|----------|----------|
| 功能点 | 入口方法/路由注解/定时任务注解 |
| 数据模型 | 实体类/表映射注解/建表脚本 |
| 接口 | 接口定义、请求映射注解、方法签名 |
| 业务流程 | 核心服务方法调用链 |
| 外部交互 | 客户端配置、主题订阅、Feign/HTTP 客户端 |
| 权限规则 | 鉴权注解/拦截器/角色判断 |

## 五、反例

- ❌ `订单模块负责订单管理`（无证据、无路径）
- ❌ `OrderService.java` 里应该有退款逻辑（"应该"= 猜测，且无行号）
- ✅ `[确证] 订单创建入口位于 OrderService.java:88（@PostMapping("/orders")）`
