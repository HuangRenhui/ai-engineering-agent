# 源码逆向挖掘

## 目的

把一份**已有项目源码**转化为结构化的、可溯源的业务与技术认知，为后续 PRD、原型、变更日志提供唯一事实来源。

## 何时使用

- 需要对存量（1+）项目补齐/重建需求与设计文档时；
- 需要梳理某模块的功能、数据、接口、流程清单时；
- 需要在不动源码的前提下理解系统全貌时。

## 前置校验（先做，不通过则停）

1. 确认目标源码根目录存在、可读、是目录。
2. 确认分析范围：有 `--scope` 则严格限定，无则先做整体画像再逐模块。
3. 确认全程**只读**：禁止修改/格式化/构建/提交目标源码。

## 工作流程

采用"全域遍历 → 先画像、后分模块 → 汇总"三段式，避免一次性读取超大仓库。

### 阶段 0：全域遍历（兜底不遗漏）

按三层清单逐一遍历，任何一项未覆盖即视为不完整；遍历结果登记 `_meta/traverse-report.md`。清单见 `references/traverse-checklist.md`：

- 前端层：路由、页面文件、弹窗组件、按钮点击事件、表单校验、接口调用点；
- 后端层：Controller、Service、定时任务、监听事件/MQ、拦截器/AOP、状态字段更新点；
- 数据层：数据表、关联关系、状态字段及枚举、更新触发条件。

### 阶段 A：项目画像

1. 识别技术栈（语言、框架、构建工具、关键依赖）与代码分层。
2. 识别模块边界（按包/目录/业务域），产出模块清单与一句话职责。
3. 识别命名约定、配置来源、外部依赖（数据库、消息、外部服务）。
4. 识别**用户角色与权限体系**：全部角色清单、鉴权逻辑（接口鉴权/路由拦截/数据权限/按钮权限，附代码证据）。
5. 产出 `_meta/project-profile.md`（模板见 `templates/project-profile.md`）。

### 阶段 B：分模块深挖

对每个（或在 `--scope` 内的）模块产出：

- **功能清单**：功能点 ID、名称、入口（路由/方法/定时任务）、前置条件、主流程要点；
- **数据模型**：表/集合、关键字段、类型、约束、关联关系；
- **接口清单**：接口路径、方法签名、入参/出参、调用方；
- **业务流程**：按**四层流程拆解法**（用户主动操作/页面联动/系统自动/后台异步）全量梳理，见 `references/four-layer-flows.md`；**分支&异常全量抓取**：逐行抓取 if/else、switch、try/catch、拦截器、校验器、状态判断，每一个判断 = 一条独立流程，禁止合并、简化、概括；
- **业务流程闭环**：每功能覆盖"初始化 → 正常操作 → 分支操作 → 异常报错 → 完成/终止 → 数据落地/回滚"；
- **外部交互**：消息主题、外部接口、第三方服务、定时任务表达式。

产出 `modules/<模块>.md`（模板见 `templates/module-inventory.md`）。

### 阶段 C：汇总

1. 合并为 `_meta/analysis-summary.md`：范围、模块清单、证据总量、置信度分布、待确认项数量。
2. 产出专项清单：权限矩阵数据（角色-页面-功能-操作）、数据字典数据（表结构/字段/枚举）、隐藏逻辑清单（未被引用组件、注释代码、TODO/FIXME、特殊兼容逻辑）。
3. 未证实的信息全部进入开放问题清单，不得进入正文。

## 证据规范

每条结论必须带证据与置信度，标注方法见 `references/evidence-spec.md`。

- 证据格式：`相对路径:行号`（必要时附最小充分片段）。
- 置信度三档：`[确证]`（有直接证据）/`[推断]`（合理推导）/`[猜测]`（仅假设，不入正文）。

## 检索策略

1. 优先使用语义/索引能力（符号查找、引用查找、调用层次）定位，再对命中位置精读，减少无关文件读取。
2. 大范围跨目录查找交给代码探索子代理（`code-explorer`）执行，避免主上下文膨胀。
3. 文本搜索仅用于**字面量**（日志文案、配置值、注释、未知模式）。

## 红线（违反即本次产出无效）

- 禁止修改目标源码；
- 禁止编造路径、类名、方法名、字段名、接口、表名、枚举、任务表达式；
- 禁止把 `[推断]`/`[猜测]` 当作已确认结论写入下游正文；
- 产物落盘前必须做敏感信息过滤。

## 输出校验（自检清单）

- [ ] 全域遍历三层清单（前端/后端/数据层）逐项覆盖，`traverse-report.md` 已产出；
- [ ] 每条结论都有 `路径:行号` 证据；
- [ ] 所有不确定项已标注置信度并登记开放问题；
- [ ] 每个功能按四层拆解完整，且通过流程闭环校验；
- [ ] 分支全量抓取：代码判断与流程条数可对照，无合并简化；
- [ ] 画像/模块/摘要/权限矩阵/数据字典/隐藏逻辑产物齐全；
- [ ] 兜底自查完成（遗漏路由/未使用组件/隐藏逻辑）；
- [ ] 产物不含敏感信息。
