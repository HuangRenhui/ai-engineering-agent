# 前端开发

## 目的

把 `prd/` + `prototype/` + `contract/` 转化为**可交互的前端页面**，并保证每个 `P`/`F` 可追溯到文件位置、每个接口调用逐字对齐契约。

## 何时使用

- 执行 `/ai-dev-frontend`；
- 需要搭建前端框架、实现页面 UI、与后端 API 对接交互；
- 需要判断"页面元素/文案是否与 PRD 原型一一对应""五态是否齐备"。

## 前置检查（阶段 1 · 基线校验）

1. **上游产物**：`prd/`（界面要素、字段规则、文案规范、AC）、`prototype/`（页面清单 = `P` 编号来源）、`permission-matrix.md`（1+，显隐依据）。
2. **契约状态**：读 `contract/README.md` 的 `status` 与 `version`，记录本次绑定的版本。
3. **技术栈**：按 `rules/dev-contract.mdc` §七 第 28 条的**命中序**解析（`--stack` → `<DEV>/_meta/tech-stack.md`（回退 `<项目>/_meta/tech-stack.md`）→ 特征探测匹配 `tech-stacks/frontend-*.md` → 系统默认 `.codebuddy/tech-stack.md` → 停下询问）。
4. **落点探测**：已有工程沿用原结构（`src/`、`app/` 等）；无则新建 `<目标项目根>/frontend/`。
5. 写 `frontend/_meta/probe.md`（含页面清单来源、开放问题带 `owner`）与 `status.md`。

## 工作流（六阶段）

| 阶段 | 名称 | 依赖 | 产物 |
|------|------|------|------|
| 1 | 基线校验 | 无 | `probe.md`、`status.md` |
| 2 | 框架搭建 | 无（**不依赖契约**） | 脚手架、目录、路由、状态管理、统一请求层、组件库 → `stack.md` |
| 3 | 页面 UI 实现 | 无（**不依赖契约**） | 逐页面对照原型与 PRD 实现，数据用 mock 或契约类型占位 → `page-impl-report.md` |
| 4 | API 绑定与交互 | **契约 `frozen`** | 逐接口替换 mock、错误码映射、五态联调 → `api-binding-report.md` |
| 5 | 契约缺口处理 | 随时 | `contract-gaps.md` + 向 `contract/_requests.md` 追加申请 |
| 6 | 报告与矩阵回填 | 阶段 4 完成 | `traceability.md` 的 `页面 P` + `前端实现` 列 |

**关键并行结论**：阶段 2、3 与契约无关，**契约未冻结也必须立即开工**；只有阶段 4 需要等待。等待期间**不得停工**，继续推进其他页面或其他阶段。

## 并行施工策略

1. 契约不存在/`draft` → 允许按 `contract/_draft/` 草案绑定，但须在 `api-binding-report.md` 标注 `草案绑定` 并在矩阵 `偏差` 列登记；
2. 契约缺项/不合理 → **禁止自行修改 `contract/`**，只做两件事：追加 `contract/_requests.md` + 在 `contract-gaps.md` 登记（现象、影响页面、临时适配方式、期望变更）；
3. 临时适配（mock / 本地兜底）必须记录，并在绑定阶段**逐一消除**；
4. 契约 `version` 落后于 `contract/README.md` → 只重做受影响页面与绑定，**禁止全量重写**；在 `api-binding-report.md` 标注"本轮重做范围 / 未受影响范围"。

## 请求层封装（契约驱动的核心）

- 所有接口调用**必须经统一 API 层**（`api/` 或画像约定目录），页面/组件**禁止**直接 HTTP；
- 路径、方法、入参、出参字段名逐字对齐 `contract/api.yaml`；类型由契约生成或手写后逐字段核对，禁止自造字段；
- 统一处理：鉴权头注入、超时、`code` 分发、错误码 → `contract/error-codes.md` 文案映射、未知错误兜底文案；
- 接口地址与环境变量一律占位符，禁止硬编码真实域名/密钥/令牌。

## 页面七对齐（逐页核对，缺一即不合格）

| 维度 | 要求 |
|------|------|
| 元素 | 字段/按钮/表格列/表单项/Tab/弹窗与 PRD「界面要素」+ 原型一一对应，不增不减，确需增减登记 `偏差` |
| 文案 | Toast/弹窗/空状态/报错**逐字取自 PRD 文案规范**（含标点），禁止改写或新造 |
| 字段规则 | 必填、默认值、输入限制（类型/长度/格式/范围）、校验时机（失焦/提交/实时）与失败文案 |
| 五态 | 每个数据页面覆盖**加载中 / 空 / 正常 / 错误 / 无权限**，且可触发或切换验证 |
| 交互闭环 | 提交类操作有 loading（防连点）、成功反馈、失败提示、二次确认（如 PRD 要求）；失败后数据保留规则按 PRD |
| 权限显隐 | 显隐条件按 PRD + `permission-matrix.md`，**禁止只样式隐藏而保留可点击能力** |
| 路由 | 路由守卫实现登录态与权限校验，未登录跳转与无权限提示文案取自 PRD |

## 产物清单

`frontend/_meta/{probe.md, stack.md, page-impl-report.md, api-binding-report.md, contract-gaps.md, status.md}` + 前端代码。

| 产物 | 必含 |
|------|------|
| `stack.md` | 画像版本、目录骨架、路由/状态管理/请求层方案、构建命令、组件库选型 |
| `page-impl-report.md` | `P ↔ F ↔ 文件:行号 ↔ 五态落实 ↔ 显隐/权限条件`、修改既有文件清单 |
| `api-binding-report.md` | `P ↔ API ↔ 调用位置 ↔ 入参/出参映射 ↔ 草案/正式 ↔ 错误码映射 ↔ 状态`、mock 残留清零结论、本轮重做范围 |
| `contract-gaps.md` | 逐条缺口：`API/P`、现象、影响页面、临时适配方式、期望变更、是否已提交 `_requests.md` |

## 自检清单

- [ ] 页面数 = 原型页面数（缺/越界均登记偏差）；`P` 编号与矩阵一致；
- [ ] 文案与 PRD 逐字一致；五态齐备且可验证；
- [ ] 无直接 HTTP 调用，全部经 API 层；字段与契约逐字对齐；
- [ ] mock 残留已清零；`contract-gaps.md` 每条均可追溯；
- [ ] `traceability.md` 的 `页面 P` 与 `前端实现` 两列已回填，**未越权写他人列**；
- [ ] 无硬编码敏感信息；产物已脱敏。

## 红线

- 禁止修改 `contract/`（只写 `_requests.md`）；禁止绕过 API 层直连；
- 禁止擅自改写 PRD 文案、增删页面元素、用前端校验替代后端校验；
- 禁止把 mock 数据写成生产逻辑而不清理；
- 禁止因契约未冻结而停工（阶段 2、3 必须推进）；
- 禁止删除既有源码、禁止 git 写操作、禁止执行白名单外命令（`rules/dev-contract.mdc` 第 32 条）。
