# 测试用例生成

## 目的

按**本次需求**产出三级可执行用例（单元 / 联调 / UAT），做到：每条 AC 有归属、每个接口有联调、每个页面×角色有 UAT，预期结果**可客观判定**。

## 何时使用

- 执行 `/ai-test-design`；
- 需要生成或补全单元/联调/UAT 用例、覆盖矩阵；
- 需要审查用例质量（字段齐全、禁模糊词、层级不重叠）。

## 前置检查（阶段 1 · 基线校验）

1. **输入探测**（结果写 `test/_meta/probe.md`）：

| 层级 | 依据产物 | 缺失时 |
|------|----------|--------|
| `TC-A` | `prd/`（AC、界面要素、文案规范）+ `prototype/` + `permission-matrix.md` | 缺失即 `blocked`（无 AC 无法写 UAT） |
| `TC-I` | `contract/api.yaml` + `contract/error-codes.md` | 生成**骨架**，待契约冻结后补齐 |
| `TC-U` | 后端 `impl-report.md` + `unit-test-report.md` + `contract/data-model.md` | 生成**骨架**，待后端实现后补齐 |

2. 记录契约 `version`；缺失项与处理方式逐条写明，不静默省略。
3. 不读源码、不改任何人产物；**只生成用例文件，不执行测试**。

## 工作流（五阶段）

| 阶段 | 名称 | 产物 | 可并行 |
|------|------|------|--------|
| 1 | 基线校验 | `probe.md`、`status.md` | — |
| 2 | 测试计划 | `test-plan.md`（范围/不测范围、数量与优先级分布、环境与数据准备、风险与依赖、执行方式说明） | 是（不依赖契约） |
| 3 | UAT 用例 `TC-A` | `test/uat/TC-A-*.md` | 是（不依赖契约） |
| 4 | 联调用例 `TC-I` | `test/integration/TC-I-*.md` | 需契约 `frozen` |
| 5 | 单元用例 `TC-U` + 覆盖矩阵 | `test/unit/TC-U-*.md`、`coverage-matrix.md` | 需后端 `impl-report.md` |
| 6 | 矩阵回填 | `traceability.md` 的 `用例 TC` 列 | — |

契约或实现缺失时**不得停工**：先做可做的层级，缺口在矩阵中显式可见，待依赖就绪后**只补该部分**，不重跑全部。

## 三级分工与不重叠原则

| 层级 | 编号 | 关注点 | 目录 |
|------|------|--------|------|
| 单元测试 | `TC-U01`… | 方法/类级逻辑：分支、边界、异常、幂等、事务回滚 | `test/unit/` |
| 联调测试 | `TC-I01`… | 接口级：参数校验、鉴权、分页排序、错误码、时序与幂等 | `test/integration/` |
| UAT 测试 | `TC-A01`… | 业务级：端到端闭环、角色差异、文案与页面表现 | `test/uat/` |

**不重叠原则**：同一关注点只写在一层——业务闭环写 `TC-A`，接口契约细节写 `TC-I`，方法分支写 `TC-U`；跨层重复须删除，或标注"验证角度不同"并说明差异。

## 字段契约（缺一即不合格）

用例编号 / 用例名称 / 关联标识（`F` 必填；`TC-I` 必填 `API`；`TC-A` 必填 `P` + 角色）/ 关联 AC（原文编号或摘要）/ 优先级（P0/P1/P2）/ 前置条件 / 测试数据（具体取值含边界，禁"任意值"）/ 操作步骤（编号，每步一动作）/ 预期结果（页面表现 + 数据变化 + 接口返回含错误码与逐字文案）/ 清理后置 / 备注（含带 `owner` 的待确认项）。

**可判定性**：推荐 Given-When-Then 或"条件→操作→预期"三段式。

**模糊词黑名单（全文命中 0）**：支持、优化、适当、可能、大概、智能、相关、友好、合理、尽快、流畅、良好、正常显示、正确返回。最后两个须改写为具体表现（如"列表展示 3 条记录，首列为订单号，格式 `SO-` 前缀 + 12 位数字"）。

文案类预期（Toast/弹窗/空状态/报错）**逐字取自 PRD 文案规范**（含标点），不得转述。

## 各层最低覆盖

| 层级 | 最低要求 |
|------|----------|
| `TC-U` | 每 `F`：主流程、边界值（最大/最小/零/空）、异常路径、幂等与事务回滚（若适用） |
| `TC-I` | 每 `API`：正常返回、入参缺失、类型/长度越界、无权限/未登录、重复提交或幂等、依赖失败（超时/5xx）、错误码与文案一致 |
| `TC-A` | 每 `F`：主业务闭环、PRD 分支流程、异常六类（网络/空数据/报错/权限/重复操作/超限）、角色差异（有权限矩阵时逐角色覆盖可见性与可操作性） |

非功能类（性能阈值、并发、兼容范围）按 PRD 非功能章节转为可测用例；写不下则登记为风险并给 `owner`，不得省略。

## 覆盖矩阵（`coverage-matrix.md`，五张表）

| 维度 | 要求 |
|------|------|
| `F × 层级` | 每个 `F` 在 U/I/A 三层各多少用例；为 0 必须写原因 |
| `AC 覆盖` | 每条 AC 被哪些用例覆盖；未覆盖逐条列风险与 `owner` |
| `API 覆盖` | 每个 `API` 被哪些 `TC-I` 覆盖；未覆盖接口列出 |
| `页面 × 角色` | 每个 `P` 在各角色下可见性/可操作性用例情况 |
| `异常六类` | 六类各自用例编号；缺类须写明"PRD 未要求"或"不适用" |

## 产物与自检

产物：`test/_meta/{probe.md, test-plan.md, coverage-matrix.md, status.md}` + `test/unit/TC-U-*.md` + `test/integration/TC-I-*.md` + `test/uat/TC-A-*.md`（可按模块合并为一份多用例文档，但编号必须连续且可检索）。

- [ ] 编号连续无重复（`TC-U`/`TC-I`/`TC-A` 各自连续）；
- [ ] 每用例字段齐全；模糊词命中 0；
- [ ] 每条 AC 有归属（覆盖或登记未覆盖 + 原因 + 风险 + `owner`）；
- [ ] `TC-I` 编号与 `API` 一一可查；
- [ ] 预期结果均可判定；文案与 PRD 逐字一致；
- [ ] `traceability.md` 的 `用例 TC` 列已回填，**未越权写他人列**；
- [ ] 接口地址/账号/令牌一律占位符，测试数据不含真实 PII。

## 红线

- 禁止执行测试、禁止修改被核验产物（只生成用例）；
- 禁止跨层重复堆用例、禁止用模糊词糊过预期结果；
- 禁止省略异常六类与权限差异；禁止用 TBD 占位替代风险登记；
- 禁止凭空造接口字段/错误码——以契约为唯一依据，缺则生成骨架并标记"待契约补齐"。
