# 统一错误码契约 · <项目名称>

> 版本：`<v0.1>` ｜ 状态：`<draft｜frozen｜changed>` ｜ 生成时间：`<YYYY-MM-DD HH:mm>`
> 用途：后端抛错、前端映射文案、联调用例 `TC-I` 断言的**唯一依据**；错误码一律用常量 / 枚举承载，禁魔法值。
> 每个错误码必须**可判定**：明确触发条件，便于写出客观预期的用例。

## 1. 编码规则

| 段位 | 位数 | 含义 | 示例 |
|------|------|------|------|
| 前 3 位 | 3 | HTTP 状态类别（200 / 400 / 401 / 403 / 404 / 409 / 500） | `400` |
| 后 2 位 | 2 | 该类下的业务序号（从 01 起） | `01` |

> 成功码统一为 `0`（或按 `<镜像既有工程约定>`），成功响应 `message = "success"`。

## 2. 通用错误码

| 错误码 | HTTP | 含义 | 触发条件 | 前端文案 | 可测 |
|--------|------|------|----------|----------|------|
| `0` | 200 | 成功 | 业务处理完成 | — | 是 |
| `40001` | 400 | 参数校验失败 | 必填缺失 / 类型不符 / 长度或范围越界 / 枚举非法 | <请输入或修正对应字段> | 是 |
| `40100` | 401 | 未登录或令牌失效 | 无 `Authorization` 头 / token 过期 / 签名错误 | <登录已失效，请重新登录> | 是 |
| `40300` | 403 | 无权限 | 已登录但无该操作权限（对齐 `permission-matrix.md`） | <没有该操作权限> | 是 |
| `40401` | 404 | 目标不存在 | 主键查无数据 / 已被逻辑删除 | <数据不存在或已删除> | 是 |
| `40901` | 409 | 唯一键冲突 | 唯一索引冲突（如 `<字段名>` 重复） | <内容已存在，请修改后重试> | 是 |
| `40902` | 409 | 并发更新冲突 | 乐观锁 `version` 不匹配 | <数据已被他人修改，请刷新后重试> | 是 |
| `40903` | 409 | 状态不允许当前操作 | 状态机非法流转（见 `enums.md` 流转约束） | <当前状态不支持该操作> | 是 |
| `50000` | 500 | 系统内部错误 | 未预期异常（禁止向前端透出栈或 SQL） | <系统繁忙，请稍后重试> | 是 |

## 3. 业务错误码

| 错误码 | HTTP | 含义 | 触发条件 | 前端文案 | 关联 F / API | 可测 |
|--------|------|------|----------|----------|--------------|------|
| `<4xxxx>` | `<409>` | <业务规则不满足> | <精确触发条件，含边界值> | <用户可读文案> | `F03` / `API-02` | 是 |

> 新增错误码必须同步：① 本文件；② `api.yaml` 对应 `responses` 描述；③ 前端文案映射；④ 联调用例。四者缺一即视为契约未冻结完整。

## 4. 前端映射约定

- 前端按 `code` 做分支：`0` 走成功逻辑，`40001` 高亮表单字段，`40100` 触发跳登录，其余走统一 toast；
- 文案以本文件"前端文案"列为准，前端不得自行改写；
- 后端不拼接用户可见文案（除 `<例外：在 message 返回具体字段名>`），文案归属由前端控制。

## 5. 异常与日志约定

- 业务异常统一抛 `<BizException>`（携带错误码），由全局异常处理器转换为统一响应；
- 未预期异常统一转 `50000`，日志记录完整栈与 `traceId`，**响应中不含栈信息、SQL、连接串**；
- 日志禁止打印口令、令牌、密钥、完整证件号 / 手机号 / 银行卡号。

## 6. 一致性校验（冻结前自查）

- [ ] 本文件所有错误码在 `api.yaml` 中均有引用（`responses` 或描述）；
- [ ] 每个错误码的触发条件可客观判定，无"视情况而定"这类模糊表述；
- [ ] 无重复码、无跳号后复用；
- [ ] 文案不含真实人名、企业名、内部系统名。
