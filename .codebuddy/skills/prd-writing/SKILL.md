# PRD 编写

## 目的

把**分析结果**（需求分析或源码逆向）转化为**逐功能、可评审、可验收、可追溯**的标准 PRD。

## 何时使用

- 0-1 模式：在需求分析完成后编写 PRD；
- 1+ 模式：在源码逆向挖掘完成后转化 PRD；
- 需要对已写 PRD 做质量审查或补全时。

## 通用工作流程

1. **确认输入齐备**：0-1 需 `<项目>/_meta/requirement-analysis.md` 与 `<项目>/_meta/tech-stack.md`（缺失则取 `.codebuddy/tech-stack.md` 系统默认并落档）；1+ 需模块清单与证据。输入不足先补齐，不硬写。
2. **PRD 必含 §技术选型与 UI 约束节**（new 模式专用；模板见 `references/tech-constraints-section.md`），内容**逐字对齐** `_meta/tech-stack.md`，禁止自行改写或扩写；如需变更，须先改 `_meta/tech-stack.md` 再回头同步本节。
3. **拆分功能点**：按用户可感知的功能边界拆分，分配稳定 ID（如 `F01-<名称>`）。
4. **逐功能编写**：按模板 `templates/feature-prd.md` 填写全部章节。
5. **汇总索引**：产出 `prd/README.md`（模板见 `templates/prd-index.md`）。
6. **质量自检**：按章节写作指南 `references/section-guide.md` 逐条核对。

## 必备结构（缺一项即为不合格）

**文档级 12 项**（全套交付物）：文档元信息（版本/状态/修订记录/术语解释）/ 需求背景（痛点数据+可量化目标）/ 做·不做范围 / 用户场景与故事（主/分支/异常）/ 全局业务流程图与页面跳转逻辑 / 逐页面详细需求（页面用途·控件规则·默认值·显隐条件·输入限制）/ 异常场景全覆盖（六类）/ 数据规则与埋点 / 非功能需求（性能·兼容·安全量化）/ 全部文案规范（弹窗·Toast·空状态·报错逐字文案）/ DoD 验收标准 / 依赖项·风险点·待确认问题。

**功能级章节**（每功能一份）：功能标识 / 背景与目标 / 使用角色 / 前置条件 / 主流程 / 分支与异常 / 业务规则 / 数据项 / 界面要素 / 验收标准 / 依赖与关联 / 开放问题。

详见 `references/section-guide.md`。量化标准见 `rules/prd-standard.mdc`。

## 验收标准（AC）要求

- 每条 AC **可客观判定真假**，禁止主观词与模糊词（黑名单见 `rules/prd-standard.mdc` §二：支持、优化、适当、可能、大概、智能、相关、友好、合理、尽快、流畅、良好）。
- 所有业务规则按**四段式具象化**：什么条件 → 展示什么 → 触发什么结果 → 报错什么。
- 覆盖：正常路径、边界值、异常路径（六类：网络/空数据/报错/权限/重复操作/超限）、权限差异（如适用）。
- 推荐 **Given-When-Then** 句式。

## 模式差异

| 维度 | 0-1（new） | 1+（evolve） |
|------|-----------|--------------|
| 需求来源 | 需求分析 / 决策记录 | 源码证据（`文件:行号`） |
| 溯源要求 | 对话轮次 / 文档锚点 | 源码证据 + 置信度标记 |
| 未证实项 | 开放问题 | 开放问题（保留 `[推断]` 标记） |

## 写作纪律

- 只写 **What（做什么、用户可感知什么）**，不写实现细节（类名、SQL、框架），除非业务规则本身依赖该技术约束。
- 术语全篇统一，必要时维护术语表。
- 结构化信息用表格，流程用编号步骤。
- 不允许遗漏任何分支逻辑：正常流程、临界值、反向操作、非法输入逐条列出。
- 所有交互闭环：加载中、成功、失败、空状态、二次确认五态的表现与文案逐一写明。
- 产物落盘前做敏感信息过滤。

## 红线

- 禁止臆造未被需求分析或源码证据支持的功能；
- 禁止把 `[推断]` 内容伪装成已确认需求；
- 禁止用 TBD 占位替代开放问题登记；
- 禁止省略复杂场景、简化异常逻辑；
- 禁止产出无法测试、无法落地的通用模板空话。

## 输出校验（自检清单）

- [ ] 全部功能点拥有稳定 ID 且已建索引；
- [ ] 文档级 12 项齐全（元信息/背景/范围/场景/流程图/逐页面/异常六类/数据埋点/非功能/文案/DoD/依赖风险）；
- [ ] 每功能章节齐全，AC 无主观词与模糊词且覆盖边界/异常；
- [ ] 每条业务规则四段式完整（条件→展示→结果→报错）；
- [ ] 每条需求可溯源（对话/文档/源码证据）；
- [ ] 开放问题均带 owner；
- [ ] 保真自检结论已写入 `prd/README.md`（业务逻辑匹配 ≥95%、场景覆盖 ≥95%、歧义 0、遗漏 ≤5%、主流程 100%）。
