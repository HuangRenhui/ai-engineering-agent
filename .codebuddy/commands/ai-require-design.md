# /ai-require-design · 0-1 智能需求定义

> 需求设计调度入口。职责：**先检查对应目录有没有逆向工程的产物（PRD 和原型）**，据此自动选择路径：
> - **未执行过 `/ai-reverse-project`（没有逆向工程产物）且未做过需求设计** → **从 0-1 开始需求设计**：仅依赖对话澄清或外部引用文件（`--doc`），不读取源码。
> - **已执行过 `/ai-reverse-project` 且已有之前的需求设计** → **继续设计**：基于现有 PRD 与原型增量迭代（不推倒重做、不停下询问）。
> 注：**逆向工程**（从 git 仓库或本地仓库深度解析源码 → PRD 和高保真原型）由 `/ai-reverse-project` 执行；本命令只做检查与调度，**不执行逆向**。

## 用法

```
/ai-require-design <项目目录或项目名> [--out=<产出目录>] [--doc=<外部引用文件路径>] [--scope=<模块或功能>]
```

参数：`$ARGUMENTS`

| 参数 | 必填 | 说明 |
|------|------|------|
| `<项目目录或项目名>` | 是 | 0-1 项目的工作目录（已存在的目录，PRD/原型与其内容**同目录存放**）或项目名称（自动新建目录）。**不要求、不读取任何源码**——本命令不依赖逆向工程产物。 |
| `--out` | 否 | 覆盖默认产出位置。默认：给定项目目录时**直接在该目录下**生成 `_meta/`、`prd/`、`prototype/`、`changelog/`、`review/`（同目录存放）；仅项目名时为 `<项目名>/docs/forward-engineered/`。 |
| `--doc` | 否 | **外部引用文件**：Word / PDF / Markdown 需求文档，作为需求的主要输入依据（不依赖逆向工程产物时，这是 0-1 的信息来源）。 |
| `--scope` | 否 | 限定范围（模块 / 功能）。 |

## 第一步：参数与前置条件校验

加载 `rules/se-workflow.mdc` §二 执行：

1. `<项目目录或项目名>` 合法：给定目录须存在（或可创建）且可写；仅项目名时自动创建项目目录。
2. `--doc` 若给定，文件必须存在且可读（`.docx`/`.pdf`/`.md`/文本）。
3. `--out` 若给定，父目录可写。
4. 校验通过后**回显执行计划**并请用户确认或中止。
5. 若用户实际诉求是对已有源码做逆向（而非从 0 定义需求），提示改用 `/ai-reverse-project`。

## 阶段 0：加载默认技术栈

【强制】0-1 开始需求设计前必须先确定技术栈，作为 PRD §技术选型与 UI 约束节的唯一依据：

1. 加载顺序（命中即止；权威定义见 `rules/dev-contract.mdc` §七 第 28 条，0-1 侧只涉及后两级）：
   - **项目级覆盖**：若 `<项目>/_meta/tech-stack.md` 存在（此前已落档或人工放置）→ 以其为准；
   - **系统默认**：否则读 `.codebuddy/tech-stack.md`（系统预置的默认技术栈，单点声明）；
   - 都缺 → **停下询问**，禁止默认。
2. **落档**：把解析结果写到 `<项目>/_meta/tech-stack.md`，作为 PRD 写作与原型生成的直接依据；同时作为后续 dev 阶段（`/ai-dev-*`）命中序第 2 级的**回退来源**（dev 侧优先读 `<DEV>/_meta/tech-stack.md`，缺失时才回退到本文件）。
3. **PRD 必含 §技术选型与 UI 约束节**（模板见 `skills/prd-writing/references/tech-constraints-section.md`），内容**逐字对齐** `_meta/tech-stack.md`，禁止自行改写或扩写。
4. **原型设计**按 `_meta/tech-stack.md` 中的前端 UI 库选视觉基线（`skills/html-prototype/references/visual-<ui-lib>.md`，默认 Element Plus → `visual-element-plus.md`）。
5. 该阶段 0 **不增加任何新命令参数**；技术栈参数 `--stack=<id>` 仍仅在 dev 阶段作为显式覆盖通道保留。

## 第二步：检查对应目录有没有逆向工程的产物（PRD 和原型）

在对应目录（项目目录；含其下 `docs/reverse-engineered/`、`docs/forward-engineered/`，以及 `--out` 指定目录）检查：

| 检测项 | 命中条件 | 含义 |
|--------|----------|------|
| 逆向工程产物 | `docs/reverse-engineered/`（或逆向 `--out` 目录）下存在 `prd/*.md`、`prototype/*.html`、`_meta/project-profile.md` 任一 | **已执行过 `/ai-reverse-project`** |
| 需求设计产物 | 检测范围内存在非空 `prd/*.md` 文件或 `prototype/*.html` | **做过需求设计** |

【强制】判定逻辑（**自动选择路径，不停下询问**）：

- **两项均未命中**（未执行过逆向工程，也没有任何 PRD/原型）→ **从 0-1 开始需求设计**，执行第三步 A。
- **已执行过 `/ai-reverse-project` 且已有需求设计产物** → **继续设计**，执行第三步 B。
- 边界情形（仅命中其一）：以"存在 PRD/原型即继续设计"为准，执行第三步 B，并在 `_meta/probe-report.md` 记录实际状态。

【强制】无论走哪条路径，都必须先写 `_meta/probe-report.md`，记录：检测时间（UTC+8 ISO 8601）、检测目录、逆向工程产物清单、需求设计产物清单、判定结论（**从 0-1 开始 / 继续设计**）、决策人（缺省为当前会话用户）。

## 第三步 A：从 0-1 开始需求设计（未执行过逆向工程且未做过需求设计时执行）

### 需求输入来源（不依赖逆向工程产物）

1. 【强制】0-1 **从 0 开始**：需求输入只有两个来源——**外部引用文件**（`--doc`）与**对话澄清**；**不读取、不依赖任何源码或逆向工程产物**。
2. 【强制】外部引用文件：用 `docx`/`pdf` 技能或直接读取，抽取角色、场景、功能诉求、业务规则、数据诉求、非功能诉求，并标注来源锚点（页码/章节/段落）。
3. 【强制】外部文件未覆盖的信息（业务目标、规则原因、权限差异、异常兜底）：走 5 类收敛问题向用户确认，禁止臆造、禁止从源码反推。

### 澄清收敛铁律（需求分析阶段的硬约束）

1. **信息不全绝不生成完整 PRD**：5 类收敛问题未闭环前，只产出需求分析草稿与开放问题，不进入 PRD 编写。
2. **必问 5 类收敛问题**（缺失即精准补问，不发散、不闲聊）：
   1. **用户角色**：功能面向哪些用户？是否区分权限/身份？
   2. **业务目标**：本次上线要解决什么具体问题？有无量化指标？
   3. **范围边界**：是否存在特殊版本、特殊人群、特殊场景不做？
   4. **核心规则**：有无行业规则、现有后台配置、业务限制、审批流程？
   5. **异常兜底**：失败后兜底策略、数据保留规则、用户提示标准？
3. **一次提问不超过 6 条**，只问能缩窄不确定性的问题。

### 流水线

> **PRD 按 `rules/prd-standard.mdc` 95% 高可信标准执行**（文档级 12 项全覆盖、禁模糊词、规则四段式、异常六类、文案逐字规范、DoD 可落地、开放问题带 owner）；不承诺与原始系统的 UI 一一对应。

| 阶段 | 执行角色 | 使用技能 | 产物 |
|------|----------|----------|----------|
| 1 需求分析 | `requirement-analyst` | `requirement-analysis`（doc 用 `docx`/`pdf`） | `_meta/requirement-analysis.md`、`_meta/open-questions.md`、`_meta/decisions.md`（决策**实时记录点**） |
| 2 PRD 编写 | `prd-author` | `prd-writing` | `prd/F*.md`、`prd/README.md` |
| 3 原型生成 | `prototype-designer` | `html-prototype` | `prototype/*.html`、`prototype/index.html` |
| 4 变更日志 | `changelog-curator` | `changelog-tracking` | `changelog/CHANGELOG.md`、`changelog/_decisions.md`（由 `_meta/decisions.md` 归并；**仅 decision 来源，无 git-commit**） |
| 5 一致性核验 | `consistency-reviewer` | — | `review/review-report.md` |

> 无源码、无 git 历史，**`git-commit` 来源缺省**（仅 `decision` 来源）。

## 第三步 B：继续设计（已执行过 `/ai-reverse-project` 且已有需求设计时执行）

> 基于现有 PRD 与原型**继续设计**：不推倒重做，只做**增量追加**与**受影响部分的修订**；已有内容默认保留。

【强制】执行顺序：

1. **读取现状**：`prd/README.md` 功能清单与 F 编号、`prd/F*.md` 全部章节、`prototype/` 页面清单、`changelog/CHANGELOG.md`。
2. **对照梳理**：将**外部引用文件与用户新增诉求**（对话 / 新的 `--doc`）与现有 PRD 对照，产出**增量清单**：
   - **新增功能**（新诉求/新文件中出现而 PRD 未覆盖）；
   - **修订功能**（PRD 已有但与新诉求不一致）；
   - **不变功能**（显式列出，本次不动）。
3. **增量执行**：
   - 新增功能：**延续 F 编号**（现有最大号 +1）追加 `prd/F*.md`，并追加对应原型页面；
   - 修订功能：仅更新受影响的 PRD 章节（主流程/规则/数据项/界面要素/AC 等）与对应原型页面，未受影响章节不改写；
   - 原型新增/修订页面后同步更新 `prototype/index.html` 导航页。
4. **文档级 12 项复核**：修订涉及范围/流程图/文案规范/埋点/依赖风险时，同步更新 `prd/README.md` 对应节与**修订记录表**（版本号 +1）。
5. **变更日志**：本次迭代的所有变更点以 `decision` 来源**追加**写入 `changelog/CHANGELOG.md` 与 `_decisions.md`，不覆盖历史。
6. **一致性复核**：`consistency-reviewer` 复核 PRD↔产物来源、原型↔PRD（**全量页面清单**，含新增与未动页面）。
7. **保真自检**：更新 `prd/README.md` 保真自检节（覆盖**全量**功能，非仅本次增量）。

【强制】迭代纪律：

- **禁止重写**未受影响的已有 PRD 章节（追加式修订，改动最小化）；
- **禁止删除或降级**已有功能（如确需移除，登记变更日志并请用户确认）；
- 新增/修订内容同样执行 `rules/prd-standard.mdc` 95% 高可信标准；
- 断点续跑沿用 `_meta/status.md`：已 `done` 的增量项不重做。

## 职责边界（本命令【不允许】做的事）

1. **执行逆向工程**（从 git 仓库或本地仓库深度解析源码 → PRD 和高保真原型）——那是 `/ai-reverse-project` 的职责；本命令只检查产物状态并调度需求设计。
2. **100% UI 还原承诺**——本命令产出的原型基于 PRD 页面清单生成，来源于需求而非源码。
3. **修改项目目录中已有的非产出文件**；`_meta/`、`prd/`、`prototype/`、`changelog/`、`review/` 属本命令产出，可正常写入。
4. **跳过检测直接跑流水线**——检测那一步是硬性必经。
5. 收到源码逆向诉求却仍跑本命令——应停下手并改派 `/ai-reverse-project`。
6. **迭代模式下推倒重做**——已有 PRD/原型只能追加与修订，禁止清空重建。

## 遵从规约

- `rules/se-workflow.mdc`（阶段状态、断点续跑、产物落盘与脱敏；产出目录以本命令约定为准：项目目录同目录存放，或 `docs/forward-engineered/`）
- `rules/prd-standard.mdc`（AC 可验证、需求溯源、开放问题带 owner）
- `rules/prototype-standard.mdc`（单文件可交互、状态覆盖、PRD 对齐——**不要求 100% 还原**）
- `rules/changelog-standard.mdc`（仅 `decision` 来源）

## 结束条件

- [ ] `_meta/probe-report.md` 已生成，结论含判定（**从 0-1 开始 / 继续设计**）。
- [ ] 从 0-1 开始：5 个阶段全部 `done`；继续设计：增量清单中"新增/修订"项全部 `done`，"不变"项显式列出。
- [ ] 产物位于项目目录下**同目录存放**（或 `--out` 指定目录）：`_meta/`、`prd/`、`prototype/`、`changelog/`、`review/`。
- [ ] 核验/复核报告确认：PRD↔需求来源（对话/外部引用文件）、原型↔PRD 全量页面清单、日志↔决策一致。
- [ ] PRD 保真自检已写入/更新到 `prd/README.md`：业务逻辑匹配 ≥95%、场景覆盖 ≥95%、模糊词命中 0、遗漏 ≤5%、主流程 100% 落地。
